# quality-wash —— 质量择优与洗版（AutoBangumi 4.0 本地插件）

按「**字幕组质量层级 → 语言档 → 分辨率 → 位深**」给每个发布打分，然后做四件事：

| 扩展点 | 作用 |
| --- | --- |
| `torrent.filter`（钩子） | 同一集的候选只放行**最优**的那一个：更差的直接拒绝，更好的到达时放行 |
| `conflict_policy`（Provider） | 重命名时目标文件名被更差的版本占用 → 返回 `replace`，**删除由宿主执行** |
| `scheduled_task`（Provider） | 定时巡检同一集里容器格式不同的重复（`.mp4` ↔ `.mkv`），清掉更差的那份（**默认 dry-run**） |
| `title.parsed`（钩子） | 把 ANi 的发布强制标成繁中 |

## 默认优先级（设置页里自由调整）

分**两个清单**：

```
优质组（自由排序，高 → 低）        垫底组（固定最后，顺序即优先级）
  喵萌奶茶屋（Nekomoe kissaten）     LoliHouse
  绿茶字幕组（Studio GreenTea）      ANi          ← 永远按繁中处理
                                    Nix-Raws

没写进这两个清单的其它组：排在优质组之后、垫底组之前。
```

* **合并发布取最高档**：`[Nekomoe kissaten&LoliHouse]` 算「喵萌奶茶屋」那一档。
* 组名匹配带词边界：`[SomeGroup] Anime Title` **不会**被误判成 ANi。
* 组之后才比语言：语言档默认 `简繁 > 简 > 繁 > 日 > 未知`。
* 想给某个垫底组升格：把它从「垫底组」删掉、加进「优质组」即可（优质组清单优先）。

## 安全护栏（都是踩过坑之后加的）

1. **只删「更好的那份已经下完」的情况** —— 更好的一份没下完时一个都不动；
2. **文件名被多个种子引用的，一律不删**（曾经因为两个种子共用同一路径，把好文件删掉过）；
3. 同一个「保存目录 + 季 + 集」桶里只留一个，且必须**严格更优**才删；
4. 首选卡住（没下完 + 群里一个做种者都没有 + 超过 `stuck_hours`）时，清掉卡住的那份，
   让次优能进来；
5. 巡检**默认 dry-run**：只在日志和通知里列出「会删什么」，确认无误后把
   `sweep_dry_run` 关掉才会真的删。

## 配置项

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | true | 总开关 |
| `groups` | 见上 | 字幕组质量顺序（高 → 低），可自由拖顺序 |
| `language_order` | `简繁/简/繁/日/未知` | 语言档位顺序 |
| `ani_always_traditional` | true | ANi 永远按繁中比较 |
| `allow_resolution_downgrade` | false | 不允许用更低分辨率替换 |
| `replace_on_conflict` | true | 重命名冲突时替换更差的版本 |
| `sweep_enabled` / `sweep_interval` | true / 900 | 定时巡检开关与间隔（秒） |
| `sweep_dry_run` | **true** | 只报告不删除 |
| `stuck_hours` | 6 | 首选卡住多久后清掉它（0 = 关闭） |
| `notify` | true | 洗版/巡检结果发通知（站内 + Telegram） |

## 安装

1. 插件目录放到 `config/plugins/local/quality-wash/`（`plugin.toml` + `quality_wash.py`）；
2. 开启未签名插件：设置 → 插件 → 「允许未签名插件」（`plugins.allow_unsigned`）；
3. 在插件列表里启用它（本地插件默认关闭）；
4. **把冲突策略槽位指向它**：`plugins.slots.conflict_policy = "quality-wash"`
   （不改的话，重命名冲突仍走宿主自带的 `replace`，跨组的洗版就不会发生）；
5. 重启容器。

## 下载顺序（在「编辑规则」弹窗里设置）

插件声明了一个前端挂载点 **`bangumi.detail.tab`**，它会出现在**编辑规则弹窗**里，
标签页名叫「下载顺序」：

* 列出**同一部番**的全部字幕组规则（按保存目录归组，所以规则重建也不会丢顺序）；
* 每行一个**下拉框选顺序**（1 = 先取），旁边 ↑ / ↓ 可微调，改完点「保存顺序」；
* 保存后写进插件自己的 `plugin_kv`（键 `orders`），并立刻在择优里生效。

**它影响什么**：同一部番、同一集，只有**顺序靠前**的那条规则的候选会被放行，
后面的会被拒绝 —— 也就是「快的在上面先取、优质补档在下面」。质量更高的版本仍然
按「优质组 / 垫底组」清单取胜并触发洗版，所以顺序不会把洗版方向带偏。

> 组件通过 `host.api.get('order', {bangumi_id})` / `host.api.put('order', …)` 访问插件
> 接口（4.0 的宿主对象结构是 `{ pluginId, api, i18n, theme, toast, events }`；
> 相对路径由宿主解析到 `/api/v1/plugins/quality-wash/` 并带上会话）。

实现：`web/order-tab.js`（原生 custom element，无构建步骤）+ 插件接口
`GET /api/v1/plugins/quality-wash/order` 与 `PUT …/order`。

## 测试

```bash
# 后端 + 择优 + 巡检 + 顺序（59 项断言）
docker exec -e PYTHONPATH=/app auto_bangumi \
  python /app/config/plugins/local/quality-wash/test_quality_wash.py

# 前端组件逻辑（11 项断言，Node + 最小 DOM 垫片，不需要浏览器）
node config/plugins/local/quality-wash/test_order_tab.mjs

# 组件语法
node --check config/plugins/local/quality-wash/web/order-tab.js
```

覆盖 7 组共 41 项断言：组档位匹配（合并发布、ANi 词边界、未知组垫底）、语言判定
（含 ANi 强制繁中）、择优打分与分辨率闸门、集数/番剧名解析、准入过滤、
冲突替换策略、巡检计划的三条护栏（共用文件 / 未下完 / 卡住）。

> 写这版时测试直接抓到一个真 bug：档位原本存的是列表下标（0 = 最好），
> 却按"越大越好"比较，导致最差的组排第一 —— 也就是说它本来会去删**好**版本。
> 现在字段叫 `group_priority` / `language_priority`，语义是"越大越好"，
> 并有专门的断言盯着。

## 已知边界

* 巡检需要读取下载器：本地插件里用了宿主内部接口（`module.downloader`），
  全部做了兜底 —— 宿主若改了接口，巡检会记日志跳过，不影响择优与冲突替换；
* 巡检按 `(保存目录, 季, 集)` 分桶，集数解析不出来的种子一律不碰（保守）；
* 洗版不会跨番剧、跨季操作。

## 库中已有保护（重建规则后不重头下）

自动读一次 Emby 里已经收录的剧集，把它们记成「已知最优」基线（默认每 6 小时刷新一次）。
之后**重新建规则、或 RSS 又把老集数推一遍**时，只要新来的并不更好就直接拒绝 ——
不用再担心「删了规则就得重头下」。

判定方式（`key()` 的同一套口径）：

| 情况 | 结果 |
| --- | --- |
| 同规格再来一份（1080p 8bit mp4） | 拒绝 ✓ |
| 规格更差（720p） | 拒绝 ✓ |
| 位深更好（10bit） | 放行 ✓ |
| 容器更好（mkv） | 放行 ✓ |
| 优质组（喵萌奶茶屋） | 放行 ✓ |
| 垫底组（ANi）即使 2160p 10bit | 拒绝 ✓（组档位优先于规格） |
| 库里没有的新一集 | 放行 ✓ |

细节：

* 基线从 Emby 的 **媒体信息**反推（容器 / 位深 / 分辨率）—— 因为 AB 重命名后的文件名
  不带字幕组，所以库里那份按「未列出组」处理：**优质组能顶掉它，垫底组顶不掉**；
* 库里那份**语言未知**，所以语言不参与和它的比较（否则一个没标语言的 10bit 好版本
  会被莫名挡掉）；正在下载的那份仍按完整口径比较；
* 基线存在插件自己的 KV 里（`library` / `library_scanned_at`），进程重启后仍在；
* 想关掉：设置里把「库里已有就不再重复下载」关掉即可（或把 Emby 地址留空）。

配置项：`known_library_guard`（默认开）、`emby_url`、`emby_token`、`library_scan_hours`（默认 6）。

## 版本号：01 与 01v2 选 v2

`01` 和 `01v2` 会被当作**同一集**（同一个桶），其余条件相同时**选 v2**。

坑在这里：SDK 给插件看的 `Release` 视图**没有版本字段**（`v2` 只存在于宿主的
`ParsedRelease.version` 上，而宿主自己的 `preference_revision()` 读的就是它）。
所以插件**自己从发布名解析**（`detect_revision`），并已用在这三处：

| 环节 | 说明 |
| --- | --- |
| 准入过滤 | `01v2` 到达时会被判为优于已下载的 `01` → 放行 |
| 库中已有保护 | 库里那份记为版本 1 → 同规格的 v2 也能放行（不会因为"已有"被挡） |
| 巡检择优 | v1 与 v2 同时在盘上时，保留 v2 / 清掉 v1 |

重命名冲突那一处不用插件解析：宿主通过 `RevisionTask.revision` 提供了版本号。

解析规则：`v` 前面不能是字母、后面不能紧跟字母数字 —— 所以 `V2Sub`（组名）、
`AV1`、`HEVC` 都不会被误判成版本号；`(v2)`、`[V2]`、`S01E05v3` 都能识别。
版本号排在 `key()` 的**最后**：字幕组 / 语言 / 分辨率 / 位深 / 容器都相同时才比它。

## 新订阅先暂停（设置里的开关，默认关）

录入新 RSS 订阅后，你可能还要先调字幕组的下载顺序 —— 打开这个开关后，
**新规则不会立刻按默认顺序开始下载**：它的种子会被拦在准入处，直到你确认。

* 开关：`hold_new_subscriptions`（默认关）；
* 打开开关的那一刻，**已存在的规则全部视为已确认**（不会被追溯暂停），之后新建的才会暂停；
* 确认方式两种，都在「编辑规则 → 下载顺序」标签页里：
  * 排好顺序点 **保存顺序** → 自动放行；
  * 想直接用默认档位 → 点 **立即放行**；
* 暂停期间标签页会显示「⏸ 待确认」提示与按钮，同时发一条站内/外部通知（标题「新订阅待确认」）；
* 「下载顺序」接口：`GET /order`（多返回 `held` / `hold_enabled`）、`PUT /order`（保存即放行）、
  `POST /order/release`（只放行，不调顺序）。
